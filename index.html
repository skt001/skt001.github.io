Cloudflare Pages / Workers の接続手順（無料枠）

このリポジトリを Cloudflare に接続するだけで、GitHub Pages と並行して配信できます。衝突は起きません。

  1. Cloudflare ダッシュボードにログイン → Workers & Pages → Create
  2. Pages または Workers（Static Assets）で GitHub リポジトリ skt001/skt001.github.io を接続
  3. 設定例（Pagesの場合）：
    • Production branch: main
    • Build command: （空欄でOK）
    • Build output directory: /（リポジトリルート）
  4. Deploy。完了すると *.pages.dev または *.workers.dev のURLが発行される

Cloudflare Workers 簡単な作り方と試用

無料枠で動く最小の Worker を作り、このページから呼び出せるようにする手順です。

  1. Cloudflare ダッシュボード → Workers & Pages → Create → Worker
  2. 名前を適当に（例: hello-skt）付けて Deploy
  3. 出てきたコードを以下のように書き換えて Save and Deploy
export default {
  async fetch(request) {
    const url = new URL(request.url);
    const name = url.searchParams.get("name") || "World";
    const data = {
      message: `こんにちは、${name}さん！`,
      time: new Date().toISOString(),
      worker: "hello-skt"
    };
    return new Response(JSON.stringify(data, null, 2), {
      headers: {
        "Content-Type": "application/json",
        "Access-Control-Allow-Origin": "*"
      }
    });
  }
};

デプロイ後、Workers のURL（例: https://hello-skt.あなたのサブドメイン.workers.dev）が発行される。

補足・注意

  • GitHub Pages と Cloudflare は同じリポジトリをソースにしても独立して動く。
  • Workers の無料枠は1日あたり一定リクエスト数まで。個人の実験用途では通常足りる。
  • CORS を通すために Worker 側で Access-Control-Allow-Origin: * を付けている。本番で公開する場合はオリジンを制限した方がよい。
  • 既存の docs/ja や docs/en のドキュメントはそのまま残してある。
