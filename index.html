GitHub リポジトリを Cloudflare で公開する手順（無料枠）

GitHub 上の静的サイト（HTML / CSS / JS）を、Cloudflare Pages や Workers でも無料で公開できます。 以下の手順で登録すると、*.pages.dev や *.workers.dev の URL が発行され、GitHub Pages と並行して配信できます。

1. Cloudflare Pages で静的サイトを公開する

  1. Cloudflare ダッシュボードにログイン → Workers & Pages → Create
  2. Pages を選び、GitHub リポジトリを接続する
  3. 設定例（ビルド不要の静的サイトの場合）：
    • Production branch: main（またはデフォルトブランチ）
    • Build command: 空欄でOK
    • Build output directory: /（リポジトリルート）
  4. Deploy すると https://プロジェクト名.pages.dev のような URL が発行される

これで GitHub Pages と同じ内容が Cloudflare 側でも公開されます。両方が同時に動いても衝突しません。

2. Cloudflare Workers で簡単な API を公開する

静的ファイルだけでなく、簡単なサーバーレス関数も無料枠で公開できます。

  1. Cloudflare ダッシュボード → Workers & Pages → Create → Worker
  2. 名前を付けて Deploy（例: hello-demo）
  3. 出てきたコードを次のように書き換えて Save and Deploy
export default {
  async fetch(request) {
    const url = new URL(request.url);
    const name = url.searchParams.get("name") || "World";
    const data = {
      message: `こんにちは、${name}さん！`,
      time: new Date().toISOString(),
      worker: "hello-demo"
    };
    return new Response(JSON.stringify(data, null, 2), {
      headers: {
        "Content-Type": "application/json",
        "Access-Control-Allow-Origin": "*"
      }
    });
  }
};

デプロイ後、https://hello-demo.あなたのサブドメイン.workers.dev のような URL が発行されます。

ブラウザや他のページからこの URL を叩くと、JSON が返ってきます。

補足：Workers でできること・できないこと

1. 役割と動作

できる

  • HTTP リクエストを受け取り、JSON や HTML を返す（Web API / サーバーレス関数）
  • V8 Isolate による極小のコールドスタート
  • ユーザーに近いエッジでの実行と自動スケール（プランごとの上限あり）
  • ReadableStream によるストリーミングレスポンスや大容量ダウンロード

できない

  • 常時起動の常駐プロセス（基本はリクエスト駆動。Cron / Durable Objects は別枠）
  • 特定データセンター（例: 東京のみ）への物理固定（グローバル分散が前提。配置のヒントは限定的に可能）

2. バックエンド連携とデータ保存

できる

  • D1（SQLite）でのリレーショナルデータの保存・検索
  • Workers KV による高速な Key-Value の読み書き
  • R2 へのオブジェクト（画像・動画など）の保存と配信
  • Hyperdrive 経由の外部 PostgreSQL 等へのコネクションプーリング
  • D1 と R2 を組み合わせたハイブリッド設計

できない

  • R2 オブジェクトに対する SQL 検索や部分書き換え（オブジェクト単位の読み書き）
  • 永続的な OS ディスクとしてのファイルシステム（ただし nodejs_compat 時は仮想 FS でリクエスト単位の /tmp 読み書きは可能。非永続・メモリ上限内）

3. プロキシと Server-to-Server 通信

できる

  • fetch() による外部 API / 他サーバーへの HTTP(S) リクエスト（BFF 的な集約など）
  • URL やヘッダーを書き換えて転送するリバースプロキシ動作
  • TCP ソケット（connect API）による外部 DB 等への接続
  • Cloudflare Tunnel と組み合わせたプライベートネットワークへのアクセス

できない

  • 送信元 IP を任意のローカル IP に偽装すること（外から見た送信元は Cloudflare の IP 帯）
  • 標準の fetch() で TLS 証明書検証をスキップすること（自己署名はそのままでは不可。公的 CA・Cloudflare Origin CA、または Custom Origin Trust Store + cots_on_external_fetch で許可する手段はある）

4. OS レベルの処理とデータ加工

できる

  • JavaScript / TypeScript によるデータ処理・パース
  • WebAssembly（C / Rust / Go 等からコンパイル）の実行
  • 標準の fetch API（multipart/form-data 等）によるバイナリの受け取り

できない

  • bash / zsh などのシェル実行
  • child_process（exec / spawn）による別プロセス起動（ImageMagick 等のバイナリ直接実行）
  • OS ネイティブの共有ライブラリ（.so 等）の読み込み

補足・注意

  • GitHub Pages と Cloudflare は同じリポジトリをソースにしても独立して動きます。
  • Workers の無料枠には1日あたりのリクエスト上限があります。個人・小規模な用途では通常十分です。
  • 上記サンプルでは CORS を通すために Access-Control-Allow-Origin: * を付けています。本番で公開する場合は、許可するオリジンを制限した方が安全です。
